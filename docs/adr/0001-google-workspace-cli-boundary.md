# Google Workspace CLI uses remote-cli with read-only service identity

Thor integrates the `gws` Google Workspace CLI through the existing `remote-cli` boundary rather than exposing Google credentials or unrestricted CLI execution inside OpenCode. The v1 integration uses a dedicated service identity mounted only into `remote-cli`, ignores repo cwd, permits only an exact allowlist of read-only Drive, Docs, and Sheets commands, and denies auth, dry-run, sanitize, file-output, export/download, and mutating commands. This keeps Google Workspace access auditable and server-policy controlled while avoiding per-user OAuth, broad discovery-driven write surfaces, and credential exposure to the agent sandbox.

The CLI runs from its private config directory because upstream loads dotenv from cwd/ancestors and caches discovery documents used to construct authenticated request URLs. Neither this directory nor raw credentials are shared with OpenCode. Resources should be shared with the service identity as Viewer; upstream's discovery-selected OAuth scopes are not themselves a read-only guarantee. See [the implementation plan](../plan/2026052001_google-workspace-cli.md) for verification and decisions.
